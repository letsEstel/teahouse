# 电脑是一层一层搭起来的

写程序之前，先弄清楚程序活在什么地方。这一节讲电脑的结构，顺便学会用终端。后面讲到 hook 时，这一节的每一个概念都会回来。

## 三层

你的电脑可以分成三层：

```text
  你写的程序、浏览器、微信         应用程序
  ─────────────────────────
  操作系统（Linux、Windows、macOS）  管理者
  ─────────────────────────
  处理器、内存、硬盘                硬件
```

硬件只会做极其简单的事：把内存里两个数加起来，把一个数写到某个位置。**操作系统**是一个特殊的程序，它管理硬件，让许多程序可以同时运行而互不干扰。

应用程序不能直接碰硬盘。它要读一个文件，只能请操作系统代劳，这种请求叫**系统调用**。这一层隔离非常要紧：操作系统正是在这里判断“这个程序有没有权限读这个文件”。茶馆的 Relay 里，最关键的一行代码就是一次系统调用，第三部分会讲到。

## 为什么要用终端

图形界面只能做设计者预先想到的事。终端是一种更直接的说话方式：你打一行字，电脑执行，告诉你结果。

这种方式有三个好处。命令可以写进文件，变成脚本，自动重复。命令可以组合，一个命令的输出接到另一个命令的输入。服务器没有屏幕，要管理它只能这样。茶馆的服务器就是这样管的。

## 打开终端

这本书使用 Linux 的命令。macOS 的终端几乎一样。

- **Windows**：以管理员身份打开 PowerShell，运行一次 `wsl --install`，重启电脑。之后打开“Ubuntu”这个应用，你就有了一个真正的 Linux 环境。茶馆的服务器也是 Linux，所以这一步值得做。
- **macOS**：按 Command + 空格，输入 `Terminal`。
- **Linux**：按 Ctrl + Alt + T。

窗口里闪烁的光标在等你输入。前面那一串提示文字叫**提示符**。等你输入、运行命令、显示结果的那个程序叫 **shell**，它也只是一个普通程序。

## 文件系统是一棵树

硬盘上的东西组织成一棵倒长的树：

```text
/                   根，一切的起点
├── home/
│   └── wang/       你的家目录
│       ├── Documents/
│       └── teahouse-book/
├── usr/
│   └── bin/        系统自带的程序
└── var/
    └── lib/
        └── teahouse/   茶馆服务器存数据的地方
```

文件夹也叫**目录**。从根开始写出的位置叫**绝对路径**，比如 `/home/wang/Documents`。

shell 在任何时刻都站在某个目录里，这叫**当前目录**：

```sh
pwd
```

```text
/home/wang
```

`pwd` 是 print working directory。从当前目录出发写的位置叫**相对路径**。`.` 表示当前目录，`..` 表示上一层，`~` 表示你的家目录。

```sh
ls
```

`ls` 列出当前目录的内容。文件名以 `.` 开头的是隐藏文件，要用 `ls -a` 才看得到。git 把仓库的全部数据放在隐藏目录 `.git` 里，茶馆把座位表放在 `.teahouse` 里，用的就是这个习惯。

## 一条命令的结构

```text
ls   -l    /usr/bin
程序  选项  参数
```

第一个词是要运行的程序，后面都是传给它的文字。`ls` 不是 shell 的一部分，它是硬盘上的一个文件：

```sh
which ls
```

```text
/usr/bin/ls
```

这一点值得停下来想一想。**命令就是程序，运行命令就是运行程序。** 你以后写的程序，和 `ls` 地位完全相同。

## 新建和移动

```sh
mkdir teahouse-book
cd teahouse-book
pwd
```

```text
/home/wang/teahouse-book
```

`mkdir` 新建目录，成功时什么也不显示。没有消息就是好消息：Unix 的程序只在有话要说时才说话，这样它们的输出才能干净地交给下一个程序。

用 `cd ..` 回到上一层。

## 每个程序结束时都会交一个数字

程序结束时交给操作系统一个数字，叫**退出状态**。0 表示成功，其他数字表示失败。这个小小的约定撑起了整个 Unix，也撑起了茶馆。

```sh
ls /usr
echo $?
ls /no-such-place
echo $?
```

```text
bin  games  include  lib  lib32  lib64  libexec  local  sbin  share  src
0
ls: cannot access '/no-such-place': No such file or directory
2
```

`echo` 把后面的文字显示出来，`$?` 是上一条命令的退出状态。

记住这件事：**git 运行 hook，hook 退出状态不是 0，推送就被拒绝。** 茶馆整套法则，最后就落在这一个数字上。

## 三条数据流

每个程序启动时都连着三条数据流：

| 名字 | 编号 | 默认接到 | 用途 |
|---|---|---|---|
| 标准输入 | 0 | 键盘 | 程序读的数据 |
| 标准输出 | 1 | 屏幕 | 程序的结果 |
| 标准错误 | 2 | 屏幕 | 给人看的消息 |

shell 可以把它们接到别的地方。`>` 把输出写进文件，`|` 叫**管道**，把前一个程序的输出接到后一个程序的输入：

```sh
ls /usr/bin > programs.txt
ls /usr/bin | wc -l
```

```text
1171
```

`wc -l` 数行数。写这一节时用的电脑上有 1171 个程序，你的数字会不同。`ls` 不知道谁在读它的输出，`wc` 也不知道数据从哪里来。这种小程序的自由组合，是 1970 年代贝尔实验室留下的设计，至今没有过时。git 把推送的信息交给 hook，用的就是标准输入。

## 这一节学到的

- 电脑分硬件、操作系统、应用程序三层，程序通过系统调用请操作系统办事。
- 文件系统是一棵树；路径有绝对和相对两种。
- 命令就是硬盘上的程序，后面跟着参数。
- 程序结束时交出退出状态，0 表示成功。
- 每个程序有标准输入、标准输出、标准错误，可以用 `>` 和 `|` 重新连接。
