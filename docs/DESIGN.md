# 设计 · Design

> 茶馆长什么样，以及为什么。写给改界面、改图标、做新平台的人。
>
> 事实以代码为准：颜色和字体的数值在 `app/src/styles/base.css`，标志的几何在 `app/src-tauri/icons/source.svg` 和 `app/src/lib/Mark.svelte`。这份文档说明它们的用途和理由，不另抄一份数值；两边对不上时，改文档。
> 设计的总方向写在说明书第六节（美学）和第十二节（M0 评审后的补充）。这里不重复，只往下落到具体做法。

## 1. 原则

茶馆的界面靠六条原则做判断。遇到这份文档没写到的情况，就回到这里。

1. **宁可美，不要廉价。** 说明书的原话是：宁可做成包豪斯风格的美丽废物，也不能做成功能齐全但看起来廉价的瑞士军刀。好看不是装饰：一群普通人愿不愿意每天打开它，第一眼就决定了。
2. **排版就是界面。** 层级靠字号、字重和留白来分，不靠卡片、阴影和底色。一页上最重要的东西应该最大。
3. **几何是唯一的装饰。** 圆、方、三角本身就够了。不用渐变、阴影、圆角卡片，也不用拟物。
4. **颜色只属于人。** 红、黄、蓝三种颜色只用来区分老板、伙计、茶客。其他一切，包括状态、提醒、差异，都用明度和形状表达。这样颜色一出现，就一定是在说“谁”。
5. **每个界面都回答“我现在能做什么”。** 每页有一个最主要的动作，按钮用动词写出后果。
6. **不让人看见技术。** 界面里没有 git、提交、分支、钥匙这些词，只有茶馆、问题、成果、提案、座位。

验收标准也是说明书定的：**每一个界面截图都值得发出去。**

## 2. 颜色

### 一张语义表

| 变量 | 用途 | 不能用来 |
|---|---|---|
| `--paper` | 底色 | |
| `--paper-deep` | 悬停、选中的浅底，差异里的成品区 | 大面积铺色 |
| `--ink` | 结构线、正文、主要按钮的实块、新增（差异里的实线）、状态的明度刻度 | |
| `--ink-2` | 辅助文字，比如后果说明 | |
| `--ink-3` | 更弱的辅助文字，删除（配合删除线） | 正文 |
| `--rule` | 细分隔线（墨色 18%） | |
| `--red` | 老板 | 警告、删除、待办数字 |
| `--yellow` | 伙计 | 文字（对比度不够），不带墨线的图形 |
| `--blue` | 茶客 | 链接、新增、按钮 |

这张表最早是 M0 评审后修正的：当时红色同时表示老板、待审数量、差异里的删除和车位占用，用户分不清。现在的规则是**一种颜色一个意思**。

几条细则：

- **黄色图形一律带一圈细墨线**（`Shape.svelte`）。黄色在米白底上对比度不够，墨线让三角在任何尺寸都看得清。
- **提醒和待办数字**用 `.badge`：墨底米白字。不用红色。
- **成果内容里的颜色**（比如车位图）必须带图例，因为它们不是这张表里的颜色。

### 对比度

辅助文字都达到 WCAG AA（4.5:1 以上），数值写在 `base.css` 每个变量旁边。夜间模式下，三原色各有一个夜间色值，图形对比度达到 3:1 以上（WCAG 1.4.11）。

### 夜间模式

夜间只换 `--paper` 和 `--ink` 两个系列，三原色的**含义**不变。所有组件只用变量，所以墨色实块（主要按钮、待办数字）在夜间自动变成米白实块，不需要为夜间单独写样式。

主题有三档：跟随系统、浅色、深色，在侧栏底部切换，记在本机。`?theme=light|dark` 用来截图。安卓外壳按页面的实际深浅给状态栏和导航栏上色（`MainActivity.kt`）。

## 3. 字体和排版

| 用途 | 字体 | 说明 |
|---|---|---|
| 中文 | 思源黑体（Noto Sans SC） | 300 到 900 都打包进应用，不依赖网络 |
| 西文、数字 | Jost | 几何无衬线，和包豪斯的方向一致 |
| 大标题 | 中文用思源黑体 900，西文用 Jost 700 | `--display`、`--heavy` 按语言切换 |

- **数字**统一用 `.num`：Jost 的等宽数字（`tnum`），编号和计数上下对齐。
- **小标签**统一用 `.label`：11 号字，字距拉开，大写。用在编号、分区名，比如“04 · 提案”。
- **正文** 15 号，行高 1.6。
- **页面标题**很大，随窗口宽度缩放（`clamp()`），比如问题页的标题从 52 到 84 像素。超大字号不能换行破坏构图，长标题用 `fit` 缩小。
- **德语**只在窄格子里允许断字（`.hyphenate`），正文和导航不断字。

## 4. 网格和间距

- **侧栏宽** `--rail`：16vw，在 200 到 248 像素之间。
- **页面左右留白** `--pad-x`、**顶部留白** `--pad-top`：都随宽度缩放。
- **断点**：

| 宽度 | 布局 |
|---|---|
| 1440 及以上 | 宽屏，原始设计 |
| 1024 到 1439 | 笔记本，侧栏收窄，座位图缩放 |
| 1024 以下 | 窄窗口和手机：侧栏变成顶栏；座位图放到内容上方；分栏页面（提案、档案）改成列表到详情两级 |

- **验收**：1366×768 下每个界面都不出现横向滚动，也不出现文字溢出。截图脚本对三种宽度和三种语言自动检查。
- **字号、间距没有统一变量**，大多写死在各个组件里。见第 10 节。

## 5. 形状和符号

### 座位

| 角色 | 形状 | 颜色 |
|---|---|---|
| 老板 | 方 | 红 |
| 伙计 | 三角，带细墨线 | 黄 |
| 茶客 | 圆 | 蓝 |
| 空座 | 墨线圆 | 无 |

**座位图**（`Room.svelte`）把茶馆画成一个方形房间：5×5 网格的外圈有 16 格，底边正中留作门，剩下 15 格正好是 15 个座位，空座也画出来。主位在上边正中，从那里开始顺时针排座：老板、伙计、茶客。你自己的座位：图形外面一个细墨框，框上写“你”，只框图形，不框名字，不用新颜色。以前的框按格子大小画死，名字一长就顶出框外（0033）；现在框跟着图形走，长名字在框下面换行。上排的座位往房间里长，下排往上长，都不会顶到墙上。

框的细节（0033，用户 2026-11-07 确认）：
- **三种角色都用方框。** 框表示“这是你的座位”，不表示角色。圆和三角放在方框里，是包豪斯常见的构图；换成圆框或三角框，放不下“你”字。
- **框往上长**，不把图形往下推：你的图形和同排邻座在一条线上。
- **名字最多两行**，再长就省略，鼠标停上去看全名。角上的座位下面紧挨着另一格，不限行数就会压上去。
- 左右两列的格子有一边压在墙上，那一边让出墙厚，名字不贴墙。

### 其他符号

| 符号 | 组件 | 画法 |
|---|---|---|
| 问题状态 | `StatusMark` | 一根横条：空心是待认领，半满是进行中，实心是已办成。只用明度 |
| 文件权限 | `AccessMark` | 铅笔是能直接改，斜箭头是改了变成提案，锁是只能看 |
| 机器成员 | `MachineMark` | 名字旁边一个墨线方框，写“机器”。不用颜色 |
| 成果类型 | `WorkGlyph`、`FileGlyph` | 墨色线条画的几何：文档是带横线的纸，表格是格子，方案是圆和方，链接是两个相扣的圆环 |
| 待办数字 | `.badge` | 墨底米白字 |

规则：**符号只用墨色**，彩色只给座位形状。新增符号时，先想能不能用已有的圆、方、三角组合出来。

## 6. 组件

| 组件 | 什么时候用 | 规则 |
|---|---|---|
| 主要动作 `.primary` | 每页最重要的一个动作 | 墨色实块，左边一个方形图标格，高 56。一页通常只有一个 |
| 次要动作 `.secondary` | 其他动作，比如“不采纳”“收起” | 墨线框，同样高 56 |
| 后果说明 `.consequence` | 紧跟在按钮旁边 | 一句话说清点了以后会怎样，13 号，`--ink-2` |
| 差异 `Diff` | 提案审阅、档案的来历 | 新增是墨色实线标记，删除是删除线加 `--ink-3`，不借用角色色 |
| Markdown 正文 | 提案、档案、问题页 | 逐节点渲染，别人写的 HTML 显示成文字（`lib/markdown.ts`） |
| 正在送出 | 任何写入 | 点下的按钮换成“正在送出…”，其他写入按钮变淡锁住，防止重复提交 |
| 已离座 | 本机的钥匙不在座位表上 | 所有写入口（标了 `data-write` 的）都收起来，只留读和带走 |
| 加载中 `Loading` | 数据还没读到 | 三个墨线形状（方、三角、圆）轮流涂黑，下面一句“正在打开茶馆”或“正在读取”。左对齐，放在页面标题的位置。300 毫秒内读到就不出现 |
| 读不到 `Loading` 带 error | 读取失败 | 用页面大标题的字号写“这一页打不开”，下面一句人话原因、一行原始信息（小字、`--ink-3`），再给一个“重试” |

**等待的规矩**（0024、0034）：
- **不留空白。** 任何时候屏幕上都要有东西告诉人现在的状态：在读、读到了，或者读不到以及为什么。
- **先给已有的，再给慢的。** 本机读一次只要十几毫秒，连服务器要几秒。文字先显示，图片随后再到；设备列表先列本机的，同步完再更新。不要让整页等最慢的那一样。
- **快的时候什么也不显示。** 加载提示晚 300 毫秒才出现，大多数时候它根本不会露面，也就不会闪一下。
- 加载不用转圈的菊花图、进度条或骨架屏。用的是座位图上已有的三种形状，只用墨色，因为彩色只留给人。

**按钮文字写后果，不写动作名。** 比如“采纳，写进茶馆”，而不是“合并”；“不采纳”下面附一句“提案退回给某某，内容不会丢”。

## 7. 动效

动效只用来表达**状态变化**，不做装饰性的循环动画。

| 动效 | 时长 | 表达什么 |
|---|---|---|
| 页面淡入 | 360ms | 换了一页 |
| 入座 | 520ms | 座位从无到有，只动一次 |
| 提案采纳后的成品 | 520ms | 内容落定 |
| 结果出现（采纳、发起提案后） | 520ms | 从左边滑进来，表示“做成了” |
| 首次引导 | 360ms | 提示出现 |
| 加载中 | 每 0.5 秒换一个 | 还在等。唯一一个循环的动效：它表达的是“还没好”这个状态，读到就消失 |

缓动曲线统一用 `--ease`（`cubic-bezier(0.2, 0, 0, 1)`）：起步快、收尾慢。系统设置了“减少动态效果”时，所有动画和过渡都关掉。

## 8. 文字

- **用动词写清后果。** 见第 6 节。
- **不出现技术词。** 见原则 6。
- **所有文字走翻译键**，不写死中文（`app/src/i18n/`）。首批三种语言：简体中文、English、Deutsch。德文角色叫 Wirt、Gehilfe、Gast，“法则”是 Gesetz。
- **按钮和标签不定死宽度**，要能装下德语长词。
- **日期本地化**：“昨天 22:14”“yesterday 22:14”“gestern 22:14”。
- **语气**：短句，先说为什么；不喊口号，不用感叹号。

## 9. 标志和图标

### 几何

标志是一个墨色的圆，里面一芽二叶（这一代的代号 Anji，安吉白茶）。三片叶子都由两段同半径的圆弧围成，茎是一根直线，底下一个小圆点。

源文件 `source.svg` 是 1024×1024 的画布：米白方底，墨色圆的半径是 350。界面里的 `Mark.svelte` 是同一份几何，颜色用 `--ink` 和 `--paper`，夜间模式自动反色。

### 各平台

| 平台 | 做法 | 理由 |
|---|---|---|
| 界面里的标志 | `Mark.svelte`，跟随主题 | 夜间不能是一块刺眼的黑圆 |
| 安卓 | **满版**：自适应图标的底色是墨色，前景只有米白的叶子；旧式图标是撑满的墨色圆 | 各家启动器用自己的形状裁剪，有圆形、圆角方块、方形、水滴形。只要边缘不是墨色，就会露出一圈白边（0021） |
| Windows、macOS、iOS | `tauri icon` 从 `source.png` 生成 | 系统不再另外裁剪 |

**安全区**：安卓自适应图标的画布是 108dp，启动器一般只露出中间约 72dp，保证可见的区域更小，大约是中间 66dp。叶子必须全部落在这里面。`source.svg` 里叶子的高度大约占画布的 46%，在安全区内。

**改标志的流程**：
1. 改 `source.svg`，同步改 `Mark.svelte`；
2. 渲染出 1024×1024 的 `source.png`；
3. 在 `app/` 里运行 `npx tauri icon src-tauri/icons/source.png`，生成桌面和 iOS 图标；
4. 运行 `node scripts/android-icons.mjs`，生成安卓的满版图标。

详见 `docs/RELEASING.md` 第 6 节。

## 10. 还没有的

这些是已知的缺口，按影响从大到小排：

1. **字号和间距没有变量。** 颜色和字体都统一了，字号、间距却散在各个组件里写死。结果是同一种东西在不同页面上可能差一两个像素，改起来要逐个找。建议先定一个字号阶梯和一个间距阶梯，再逐页替换。
2. **安卓 13 的主题图标。** 安卓 13 起，用户可以让图标跟随壁纸配色，这需要一张单色图层（`monochrome`）。我们现在没有，打开这个选项时，系统会保留原样的墨色图标。
3. **没有最小尺寸规则。** 桌面版的任务栏和浏览器标签页会用到 16 和 32 像素的图标。陈列页里 16 像素的标志，叶子已经很难辨认，只剩一个墨色圆点。常见做法是给小尺寸单独画一版简化的图形，比如只留中间一片叶子。

## 11. 怎么验收

- **陈列页**：开发时打开 `#/<茶馆>/design`（假数据或开发服务器才有），所有颜色、字体、符号和组件的状态都在这一页。改了样式先看它。截图脚本每轮也拍它。
- **截图**：`npm run shoot -- <轮次>-<简述>`。默认只拍 1366 宽的中文一组，加上本轮新增的界面和夜间模式。溢出检查对三种宽度、三种语言全部运行。
- **对比度**：新加颜色时，在 `base.css` 里写明它和底色的对比度。
- **真机**：涉及图标、状态栏、键盘、刘海的改动，要在安卓模拟器或真机上看一眼。浏览器里看不出来。
